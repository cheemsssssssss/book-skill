# 调试手册：症状 → 病因 → 处置

调试的核心原则：**二分**。先确认"数据到底有没有拿到"，再确认"规则有没有选中"。不要靠猜。

## 0. 建立基线

调试任何问题前，先做一次原始抓取，确认 App 看到的世界和你看到的一样：

```bash
node scripts/fetch-probe.mjs "<目标URL>" --save /tmp/p.html
```

输出会给出：状态码、Content-Type、字节数、检测到的编码、前 200 字符。

如果这一步就拿不到正确内容，**后面所有规则都不用看了**。

## 1. 症状对照表

| 症状 | 最可能的原因 | 处置 |
|---|---|---|
| 搜索返回空列表 | 关键词没 URL 编码 | `{{key}}` → `{{java.encodeURI(key)}}` |
| 搜索返回一堆推荐书（不是搜索结果） | 站点无结果时回落到首页推荐 | 填 `checkKeyWord`，让 App 判为无效结果 |
| 搜索出书但书名全空 | `bookList` 选中了容器但 `name` 路径不对 | 单独测 `name`，注意是否需要 `@tag.a@text` |
| 只出 1 本书 | `bookList` 结尾误加了 `@text` | 去掉属性，列表规则只返回节点 |
| 点进书详情页空白 | `bookUrl` 取到的是相对路径且跨了子域 | 改用绝对地址，或用 JS 拼 `baseUrl` |
| 目录为空 | `tocUrl` 错了，或目录是异步加载 | 先确认 `tocUrl` 打开的页面里有没有章节 |
| 目录只有前 20 章 | 缺 `nextTocUrl` | 抓第 2 页目录，写分页规则 |
| 正文为空但目录正常 | 正文页要 `Referer`，或内容是 JS 注入 | 补 header；或改用 `sourceRegex` |
| 正文只有一句话 | 正文被分页，缺 `nextContentUrl` | 抓第 2 页，写分页规则 |
| 正文带广告/水印 | 没做清洗 | `##正则##` 或 `replaceRegex` |
| 全是乱码 | 编码不是 UTF-8 | 见 §3 |
| 403 / 521 | 反爬 | 见 §4 |
| 偶发失败、重试就好 | 触发限速 | 设 `concurrentRate`，加大间隔 |
| 导入失败 | JSON 语法错 / header 类型错 | 跑 `validate-booksource.mjs` |

## 2. 逐字段定位法

出问题时按这个顺序缩小范围，每一步只回答一个问题：

1. **页面拿到了吗？** → `fetch-probe` 看状态码和 body 长度。
2. **节点选到了吗？** → 在本地文件里 `grep` 一下目标 class 是否存在。
3. **选到几个？** → 数一下 `grep -c 'class="item"'`。数量为 0 = 选择器错；数量为 1 但应有 20 = 选择器命中了外层容器。
4. **属性对吗？** → 看该节点的实际 HTML，确认是 `href` 还是 `data-url`，是 `text` 还是藏在子节点。
5. **值被清洗坏了吗？** → 临时去掉 `##` 部分，看原始值。

```bash
# 例：确认列表项 class 到底叫什么
grep -o 'class="[^"]*item[^"]*"' /tmp/s.html | sort | uniq -c | sort -rn | head
```

这一步能立刻发现"你以为叫 `book-item`，实际叫 `book-item clearfix`"这类问题（CSS 里 `class.book-item` 对多 class 是能匹配的，但 `[class="book-item"]` 不能）。

## 3. 编码问题

**症状**：正文/书名是 `锟斤拷`、`ä¸­æ–‡`、`????`，或整个页面是方框。

**判定**

```bash
# fetch-probe 会打印检测到的编码；也可手动看
grep -io 'charset=[^"> ]*' /tmp/p.html | head -3
```

**处置**

- 页面声明 GBK/GB2312，但 App 按 UTF-8 解 → 这类站通常在响应头里没写 charset，需要 App 侧处理；书源层能做的是**换用接口**（接口一般是 UTF-8），或改用 `webJs`。
- 如果只是少量字符乱，可能是 `&nbsp;` `&#39;` 这类实体没解码 → 用 `##&nbsp;## ##` 清洗。
- 判断是"真乱码"还是"实体未解码"：`ä¸­æ–‡` 是 UTF-8 被当 Latin-1 读，属于前者；`&#20013;` 属于后者。

## 4. 反爬

按成本从低到高试，每步只加一个变量：

1. **加 UA**：`header` 里给一个真实浏览器 UA。
2. **加 Referer**：很多站校验来源页。
3. **加 Cookie**：从浏览器复制，注意会过期，不要写进要分享的源。
4. **降速**：`concurrentRate: "1000"`。
5. **换入口**：移动版域名（`m.`）、旧版路径、AMP 页，往往没有反爬。

仍然 403/521 就停手。硬刚的收益极低，且交付出去也是废源。

## 5. 分页

三种分页，别混：

| 类型 | 字段 | 特征 |
|---|---|---|
| 搜索/列表分页 | `searchUrl` 里的 `{{page}}` | URL 里有 `page=2` |
| 目录分页 | `ruleToc.nextTocUrl` | 目录页底部有"下一页"，或 `?page=2` |
| 正文分页 | `ruleContent.nextContentUrl` | 正文页底部有"下一页"，URL 常是 `1.html` `2.html` |

`nextTocUrl` / `nextContentUrl` 要返回**下一页的地址**（字符串），不是布尔。取不到时返回空字符串表示没有下一页。

## 6. 懒加载与异步

**症状**：目录/正文只有一部分，或者图片地址是 `data-original`。

**处置**

- 图片：`tag.img@data-original||tag.img@src`。
- 目录异步：找它请求的接口（通常 `/api/chapters?bookId=`），直接把 `tocUrl` 指向接口，用 JSONPath 解析。
- 正文异步：只能 `webJs`。

## 7. 规则写对了但还是空

按概率排查：

1. **JSON 转义**：`\s` `\d` `\w` 在 JSON 字符串里必须写成 `\\s` `\\d` `\\w`。这是最高频的低级错误。
2. **规则值首尾有空格**：从 DevTools 复制选择器时容易带进来。
3. **大小写**：HTML 属性值区分大小写。
4. **多 class**：`class="a b"` 用 `class.a` 能匹配，用 `[class=a]` 不能。
5. **iframe**：内容在 iframe 里，书源取不到，只能放弃。
6. **规则顺序**：`bookList` 必须在字段规则之前生效；如果 `bookList` 是空的，所有字段都空。

## 8. 调试记录模板

每个源调完后记一份，方便日后修：

```
站点：example.com
类型：B 接口型
验证：2026-11-01，搜索"测试"→ 20 条；《书名》→ 目录 120 章 → 正文完整
限制：目录仅前 300 章可见（站点限制）
失效预案：接口路径变更时改 searchUrl；封面域名换 CDN 时改 coverUrl
```
